 A value of 0 means count cycles, otherwise selects event to count. When PERF_MODE is one of the latency counters this is the event that is used to indicate the start. Note that when counting latency it is expected that there is always an end event before another start event is seen, and there is always one and only one start event for every end event. Behavior is undefined if these are violated. Latency counters do not begin until the start trigger has been triggered. EVENTS NOT CORRECT NEED UPDATE VMC has 20 events. These events include event 1 = number of bank0 pte cache requests event 2 = number of bank0 pte cache hits event 3 = number of bank0 pte cache misses event 4 = number of bank1 pte cache requests event 5 = number of bank1 pte cache hits event 6 = number of bank1 pte cache misses event 7 = number of pde0 cache requests event 8 = number of pde0 cache hits event 9 = number of pde0 cache misses event 10 = number of faults event 11 = number of faults by client-id event 12 = number of bank0 4k pte cache hits event 13 = number of bank0 4k pte cache misses event 14 = number of bank0 bigk pte cache hits event 15 = number of bank0 bigk pte cache misses event 16 = number of bank1 4k pte cache hits event 17 = number of bank1 4k pte cache misses event 18 = number of bank1 bigk pte cache hits event 19 = number of bank1 bigk pte cache misses event 20 = number of l2 cache invalidations (if VM_INVALIDATE_REQUEST used one for every bit set)
